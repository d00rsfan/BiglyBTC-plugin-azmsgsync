# BiglyBTC-plugin-azmsgsync

Bounded static key/envelope and legacy STS libraries at original azmsgsync baseline
`4209aa5029e3035cbb09dc3a83e9491d3f36fbc6`. This is not an operational message
sync plugin. No sockets, DHT, real identities, profile/config files or chat are
accessed. Protocol/identity/signature/STS verification and replay/order handling
remain required before plaintext is admitted as a message.

The native model preserves user-key folding with the original constant/SHA1,
16-byte general secret,20-byte listen/call key and peek-key bit change, plus
24-byte private shared-secret fixing (short values zero-padded, long values use
their trailing24 bytes). General envelopes use AES128-CBC and private envelopes
AES192-CBC, original PKCS padding and a16-byte IV prefix. OpenSSL3.5.5 supplies
the primitives and fresh cryptographic IVs for native encryption. These are
compatibility primitives for the original protocol, not a new message format.

The reference harness uses exact method bodies and the bounded original init
key block, supplied fields, original SHA1 and vendored BouncyCastle helpers.
The original SunJCE general path returns empty bytes for an IV-only envelope;
the private BouncyCastle path rejects it. Native preserves that distinction.
Malformed padding returns an explicit error and cleanses intermediate plaintext.
Input/output and user-key/shared-secret limits are4MiB and64KiB respectively.
The caller owns its input secrets, derived keys and returned plaintext.

The STS primitive follows the unchanged core CryptoSTSEngineImpl/CryptoECCUtils
at cb8c6cb9bb97916cbc7e80338a017200ffc3e71f: prime192v2, SHA1/ECDSA, version1
length-prefixed key/auth packets and the vendored positive BigInteger shared
secret representation. It uses fresh native ephemeral keys/nonces and preserves
compressed25-byte and uncompressed49-byte public keys. Exact encoded peer identity
binding is required; equivalent point encodings are not interchangeable identities.
Secrets are owned move-only buffers, with internal derivation/import scratch
cleansed. Caller-owned key inputs, copies/derived keys and plaintext remain the
caller's responsibility. No production identity is loaded/generated by this API.

Application secret access requires both successful peer authentication and an
explicit expected public key. The original raw pre-auth getter is represented
only as derived-state diagnostics. A self-signed key packet alone does not grant
application key access. Native inputs are limited to128KiB per packet;16-bit field
framing and source cursor/phase behavior are retained. The native implementation
rejects invalid curve points using OpenSSL validation. The original accepts one
signed off-curve (0,0) fixture; its unchanged observations and the exact required
native rejection are separately retained in sts-fixtures/native-policy.json.
No complete original malformed-input acceptance equivalence is asserted.

Portable tests cover313 original frame/phase cases (1033 observations, two
explicit invalid-point state differences),225 Java integer vectors, ownership/
auth/binding/reset/bounds checks and the existing envelope fixtures. Local
source-built Java/native mutual handshakes additionally verify both directions
and original private-cipher readbacks, including actual23-,24- and25-byte secrets.
The only static identity vector is public test scalar ONE; it is never a shipped
or automatically selected runtime identity. The library requires the qualified
C++23 compiler/standard-library snapshots and OpenSSL3.5.5.

Remaining work includes original persisted identities/history, signature/STS
integration, bencoded wire maps/compression, DHT/database transfer, privacy/network
separation, plugin lifecycle and UI. No publication or source/binary release is
enabled by this library. GPL-2.0-or-later; original Copyright2014 Azureus Software.

## Continuous integration

The workflow is [`.github/workflows/compatibility.yml`](.github/workflows/compatibility.yml). [View runs](https://github.com/d00rsfan/BiglyBTC-plugin-azmsgsync/actions).

The workflow runs on GitHub-hosted `ubuntu-26.04` amd64 runners on pushes, pull requests, and manual dispatch. It installs the exact GCC16/libstdc++16 snapshot and pinned Ubuntu dependency packages declared in the workflow; no separately provisioned runner is needed. GCC Release and GCC ASan/UBSan/LSan Debug replay the unchanged offline fixtures and boundary tests. Clang24 remains separately qualified by the local evidence; this hosted workflow does not claim a Clang run. Build/test logs and installed package versions are retained as workflow artifacts. This CI does not publish a release or qualify other distributions.

For future workflow changes, push using this repository's SSH URL (`git@github.com:d00rsfan/BiglyBTC-plugin-azmsgsync.git`). HTTPS pushes authenticated with an OAuth token require the additional `workflow` scope to add or update workflow files. Viewing public Actions runs does not require that scope.
